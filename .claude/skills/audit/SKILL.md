# audit — 見落としを自分で探して直す

## この skill の存在理由

このリポジトリで実際に起きた漏れは、**どれも lint とテストを通り抜けていた**。

| 実際にあった漏れ                                                      | なぜ通り抜けたか                                   |
| --------------------------------------------------------------------- | -------------------------------------------------- |
| error boundary が Next.js 15 の `reset` のまま（#35）                 | 型は通る。押しても再フェッチしないだけで、落ちない |
| `(auth)` に loading/error が無い（#35）                               | 規約は AGENTS.md の文章にしか無かった              |
| `<Button render={<Link/>}>` が `<a>` に `type="button"` を吐く（#36） | dev の警告のみ。CI は無言                          |
| アイコンボタンに名前が無い（#38）                                     | 見た目は正しい。読み上げでしか露見しない           |
| 設計書の9つの図のうち4つが実装と矛盾（#34）                           | 図は実行されない                                   |

**共通点は「落ちないから気付けない」。** だから探しに行く仕組みが要る。

## 手順

### 1. 前提

```bash
git branch --show-current && git status --short && gh pr list --state open
```

作業ツリーが汚れている、またはオープン PR があるなら**何もせず終了**する。
ユーザーの作業中に割り込まない。main にいることを確認する。

### 2. 機械的な検査

```bash
pnpm format:check; pnpm lint; pnpm check:conventions; pnpm typecheck; pnpm test:coverage
npx supabase status >/dev/null 2>&1 && pnpm test:e2e
```

ここで落ちたものは**確実な不具合**。最優先で直す。

### 3. 観点をひとつ選んで深掘りする

機械的な検査が全部通ったら、以下から**まだ見ていないものをひとつ**選ぶ。
毎回ぜんぶをやろうとしない——浅く広くやると何も見つからない。

直近の実施状況は `git log --oneline -20` と `gh pr list --state merged --limit 10`
から読む。同じ観点を続けて繰り返さない。

| 観点                        | 具体的に何をするか                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Next.js の API ドリフト** | `node_modules/next/dist/docs/` の該当ガイドを読み、使っている API が現行の作法か確かめる。**学習データは古い。** 「Version History」表と deprecation 注記を必ず見る            |
| **ライブラリの実装確認**    | 警告や不可解な挙動があれば `node_modules/` のソースを読んで原因を特定する。警告文の助言が正しいとは限らない（#36 は "set `nativeButton` to `false`" に従うと a11y が悪化した） |
| **a11y**                    | 名前は #38 で揃えた。残りはコントラスト比・フォーカス可視性・キーボード操作順序・フォームのラベル関連付け                                                                      |
| **認可の穴**                | `src/services/` の各メソッドで `authorize()` の第4引数（本人限定チェック）の渡し忘れが無いか。RLS が主防御ではないことを踏まえて Service 側を見る                              |
| **設計書と実装の矛盾**      | `docs/design/user-flows.md` の図を実装と突き合わせる。`docs/database/authorization-matrix.md` と `src/services/` の実際の判定                                                  |
| **エラーパスの挙動**        | 失敗時に何が起きるか。握り潰し、誤ったフォールバック、ユーザーに出ない失敗                                                                                                     |
| **テストの穴**              | カバレッジ100%でも通る穴。境界値、Zod の enum 外、認可の1つ下のロール                                                                                                          |

### 4. 見つかったら直す

`/ship`（`.claude/skills/ship/SKILL.md`）に従って main まで運ぶ。
設計書の追随と ADR もそこに含まれる。

**1回の実行で1つのテーマに絞る。** 無関係な変更を混ぜた PR はレビューできない。

### 5. 見つからなかったら何もしない

**これが最も重要。** 何も見つからないのは正常な結果であって、失敗ではない。

- コミットしない。PR を作らない
- 「念のため」のリファクタをしない
- 動いているコードを好みで書き換えない
- 依存を理由なく上げない
- 検査を通すために閾値や検査自体を緩めない

「何も見つからなかった。次は〈観点〉を見る」と報告して終える。

## 報告

- **何を見たか**（観点と、実際に読んだファイル・ドキュメント）
- 見つけたもの、または見つからなかったこと
- 次に見る観点

## やってはいけないこと

- 作業ツリーが汚れている / オープン PR がある状態での割り込み
- `main` への直接コミット
- カバレッジ閾値の引き下げ、`scripts/audit.mjs` のチェック削除、
  ESLint ルールの無効化。**検査が落ちたら検査ではなく実装を直す**
- 仕事を作るための変更。**何もしないことを選べる**
- 事実と違う報告。直っていないものを直ったと言わない
