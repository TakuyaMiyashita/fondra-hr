# 0003. 従業員レコードと未紐付けのユーザーは何も見えない側に倒す

**状態**: 採用

## 背景

「自分が当事者のデータだけ扱える」という制御は、ログインユーザー（`auth.users`）と
従業員レコード（`employees`）の突き合わせが前提になる。紐付けはメールアドレスで
自動的に行われるが、メール未登録・不一致のユーザーは紐付かない。

その場合に `getOwnEmployeeId()` は `null` を返す。この `null` をどう解釈するかで
挙動が正反対になる。

## 決定

**`null` は「チェック不要」ではなく「操作不可・閲覧不可」に倒す。**

## 理由

`null` を「チェック不要」と解釈すると、**紐付いていないユーザーに全社のデータが
開く**。しかも `employees.user_id` はマスタ登録直後は必ず空なので、
「まだ紐付いていない大量のレコード」が常に存在する。ここを緩めると、
制御が最も効いていてほしい状態でだけ制御が外れる。

安全側に倒した結果、紐付いていない member は 1on1 も評価も作れず何も見えない。
運用上はメールを登録すれば解決するため、失敗の代償が小さい。

## 実装上の注意

`src/services/self.ts` の docstring に同じことを書いてある。新しく
`getOwnEmployeeId()` を使うときは `null` の扱いを必ず確認する。
