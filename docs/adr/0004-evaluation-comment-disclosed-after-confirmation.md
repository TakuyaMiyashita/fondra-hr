# 0004. 評価コメントの本人開示は確定後のみ

**状態**: 採用

## 背景

評価コメントは機微な情報で、当初は**被評価者本人にも一切見せていなかった**。
理由は「開示フローが未実装だから」で、フローを定義すれば緩められる状態だった。

`evaluations.status` は `draft` / `in_progress` / `submitted` / `confirmed` / `returned`
の5状態を持つ。どこから本人に見せるかを決める必要があった。

## 決定

- **被評価者本人には `confirmed` の評価のコメントだけ返す**
- 評価者本人は状態に関わらず読める（書いた本人なので隠す理由が無い）
- **`confirmed` への遷移は admin 以上に限定**
- **確定済み評価の編集も admin 以上に限定**

## 理由

- `submitted` から開示する案も検討したが、**admin のレビュー前の内容が本人に
  流れる**。書き手が推敲できないまま評価が伝わるのは、評価制度として望ましくない
- **確定は開示のスイッチそのもの**なので、評価者が自分で倒せると、開示の
  タイミングを評価者が握ることになる。だから admin 以上に限定した
- 確定後の編集を塞ぐのは、**本人が読んだ内容を評価者が後から差し替えられると
  確定の意味が無くなる**ため。修正が必要なら admin が行う

## 捨てたもの

`returned`（差戻し）で非開示に戻す設計。状態遷移が複雑になる割に、
一度読まれた内容は取り消せないため実効性が薄いと判断した。
