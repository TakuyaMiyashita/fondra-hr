# 0005. 本番環境を作らず検証環境ひとつで運用する

**状態**: 採用

## 背景

一般的には本番と検証（staging）を分ける。しかしこのプロジェクトは
ポートフォリオであり、実ユーザーを持たない。

## 決定

**検証環境ひとつのみを運用する。** 本番環境は作らない。

## 理由

- 実ユーザーが居ないため、環境を分けて得られる「本番を壊さない」という
  利点が存在しない
- **`supabase/config.toml` は単一環境しか表現できない。** 環境を分けると
  `site_url` などを push のたびに手で直す運用が発生する。得るもののない
  複雑さを抱え込むだけになる
- 検証環境のデータはいつでも作り直してよい前提にすることで、
  マイグレーションやシードの検証が気軽にできる

## 影響

本番運用に切り替える場合に変更が要る設定（メール確認・レート制限・
パスワード長・バックアップ）は [デプロイ手順](../deployment.md) に併記してある。
