# 0008. スキルの入力候補は DB ではなくコードに置く

**状態**: 採用

## 背景

スキル名もカテゴリも素のテキスト入力だった。表記ゆれ（`フロントエンド` /
`フロント` / `Frontend`）がそのまま登録でき、カテゴリのフィルタが機能しなくなる。

さらにカテゴリの選択肢は `getCategories()` が既存の skills から
`selectDistinct` で導出しているため、**1件も登録されていない組織では
選択肢が空**になる。最初の1件を作るときに何の助けも無い状態だった。

## 決定

**入力候補は `src/lib/constants/skill-presets.ts` に定数として持つ。**
DB のマスタテーブルにはしない。

**候補であって強制ではない。** Base UI の `Autocomplete` で
「候補から選べるが自由入力もできる」形にする。

## 理由

- **プリセットはテナントデータではない。** 全テーブルに
  `org_id uuid not null` を要求する規約と噛み合わず、
  `scripts/audit.mjs` の `org-id` 検査を通すために不自然な設計を強いられる
- マスタテーブルにすると、マイグレーション + RLS + Drizzle 定義 +
  シード投入が要る。得られるものは「候補が出る」ことだけで見合わない
- **自由入力を止めない。** 企業固有のスキル（社内システム名、独自の職能）を
  登録できなくなる。表記ゆれの抑止と、登録できないことは別の問題

`Combobox` ではなく `Autocomplete` を使うのは、Base UI 自身が
「Combobox does not allow free-form text input」と明記しているため
（`node_modules/@base-ui/react/docs/react/components/autocomplete.md`）。

## 捨てた案

| 案                                               | 却下理由                                                                              |
| ------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `skill_presets` テーブルを作る                   | テナントデータでないため `org_id` 規約と衝突する。DB スキーマ変更に見合う利点が無い   |
| `category` を enum / CHECK 制約にする            | 自由入力を許す決定と矛盾する。既存データの移行も要る                                  |
| `skill-form-dialog.tsx` にローカル定数として置く | カテゴリ側の候補と seed のパリティテスト、2箇所から参照するのでコロケーションが破れる |
| `seed.sql` を TS から生成する                    | codegen ステップが増え、`supabase db reset` の自己完結性が壊れる                      |

## 影響

**`supabase/seed.sql` のデモデータと同じ内容を保つ。** ズレると
「デモを見て触ったら候補に出てこない」が起きる。
`tests/unit/skill-presets.test.ts` が seed の投入ブロックを正規表現で抜いて
突き合わせ、ドリフトを機械的に止めている。seed.sql は
`supabase db reset` から単独で使える純 SQL のまま保つ。

**既に登録済みのプリセットも候補から消さない。** ダイアログが持っている
skills は現在のフィルタ / ページ50件分でしかなく、「消えている＝登録済み」が
嘘になるケースがある。重複は `createSkill` が拒否し、toast で伝える
既存の経路をそのまま使う。

**候補から選んだときだけカテゴリを自動で補う。** 自由入力では触らない
（打っている途中で勝手に変わるのは事故）、編集モードでは触らない
（名前を打ち直した拍子に既存のカテゴリが飛ぶ）、ユーザーが自分で触った
カテゴリは上書きしない。

**候補が1件も無いときはポップアップを出さない。** 空の箱がフォームの
送信ボタンを覆い、自由入力した値をそのまま登録できなくなるため。
「そのまま入力できる」ことは、常時表示の補足文で伝える。
