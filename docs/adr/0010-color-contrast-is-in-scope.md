# 0010. 配色のコントラストも担保する（0009 のスコープ判断を上書き）

**状態**: 採用

**上書き対象**: [0009](./0009-form-a11y-wiring-lives-in-base-ui-field.md) の
「配色とコントラストは今回見ていない」というスコープ判断

## 背景

0009 では a11y の対象を「フォーム関連 + キーボード到達性」に絞り、配色を
明示的にスコープ外とした。その後に実測したところ、想定より悪かった。

| 対象                               | light         | dark                     | 必要 |
| ---------------------------------- | ------------- | ------------------------ | ---- |
| フォーカスリング（`ring-ring/50`） | **1.54:1**    | **1.87:1**               | 3.0  |
| `--chart-1`                        | **1.48:1**    | 13.36:1                  | 3.0  |
| `--chart-3 / 4 / 5`                | 7.8〜15:1     | **2.54 / 1.91 / 1.31:1** | 3.0  |
| 本文 / `--muted-foreground`        | 19.8 / 4.73:1 | 19.0 / 7.63:1            | 4.5  |

テキストは問題なかった。**問題は非テキスト（SC 1.4.11）に集中していた。**

`--chart-*` が light / dark で同じ値だったため、**どちらのモードでも一部の系列が
背景に沈む**構造になっていた。グラフの系列が見分けられないのは配色の好みではなく
機能の欠落である。

## 決定

**非テキストのコントラストも 3:1 以上を満たす。** テキストは 4.5:1。

- `--ring` を light で `0.708` → `0.6` に下げる（`--sidebar-ring` も揃える）
- **フォーカスリングの不透明度を戻す。** `globals.css` の**レイヤー外**に
  `*:focus-visible { --tw-ring-color: var(--ring); }` を置く
- `--chart-1`〜`5` を light / dark で別の値にする

## 理由

### なぜ不透明度を戻すのか（トークンの値だけでは直せない）

`ring-ring/50` は 50% 不透明。白背景に重ねると、**`--ring` を純黒にしても
3:1 にぎりぎり**で、50% のまま条件を満たすには `L <= 0.288` が要る。
同じトークンを使う `focus-visible:border-ring` まで真っ黒になり見た目が壊れる。

100% にすれば `L <= 0.669` で足り、`0.6` なら 3.95:1 と余裕がある。

### なぜレイヤー外に書くのか

`focus-visible:ring-ring/50` は `src/components/ui/` の7ファイルにあり、
ここは「shadcn 自動生成・手動編集しない」方針。触ると `shadcn add` のたびに
差分が戻る。

Tailwind のユーティリティはすべて `@layer utilities` の中にあり、
**レイヤー付き規則はレイヤー無し規則に必ず負ける**。`!important` を使わずに
上書きできる。

### なぜ無彩色のままか

有彩色のパレットにすれば系列の識別性は上がるが、現在のモノトーンな
デザイン方針から外れる。**まず「沈んで見えない」を解消する**ことを優先し、
色相での区別は必要になった時点で別途判断する。

## 捨てた案

| 案                                                   | 却下理由                                                            |
| ---------------------------------------------------- | ------------------------------------------------------------------- |
| `src/components/ui/` の7ファイルを直接編集           | `shadcn add` のたびに差分が戻る。規約違反                           |
| `--ring` を `L <= 0.288` まで暗くして 50% のまま使う | `border-ring` が真っ黒になる。フォーカス時の枠が重すぎる            |
| `!important` で上書き                                | レイヤー外に置けば不要。`!important` は次に上書きしたい人を詰ませる |
| 有彩色のチャートパレット                             | デザイン方針から外れる。識別性の向上は別問題として扱う              |

## 影響

**`tests/e2e/a11y-contrast.spec.ts` が実ブラウザで検証する。**
トークンの値ではなく、**ブラウザが解決した色**を canvas に描いて測る。
`getComputedStyle` は oklch を `lab()` のまま返すことがあり、文字列から
数値を拾うと RGB として誤読するため。

フォーカスリングは Tab で辿って測る。**`:focus-visible` はスクリプトからの
`focus()` では一致しない。** また `boxShadow` の文字列には ring-offset の
透明値が先に並ぶので、そこから色を拾うと透明を掴む。`--tw-ring-color` と
`--tw-ring-shadow` を直接見ること。

axe の `color-contrast` は**テキストしか見ない**ため、この検査の代わりには
ならない。`a11y-axe.spec.ts` の除外はそのまま維持する。

**維持する理由はスコープではなく、axe が `lab()` を誤読することにある**
（2026-08-27 に実測して追記）。試しに除外を外すとダイアログ3画面で
`color-contrast` 違反が出たが、いずれも false positive だった。

| 対象                                  | 値                                                   |
| ------------------------------------- | ---------------------------------------------------- |
| `getComputedStyle` が返す色           | `lab(48.496 0 0)`                                    |
| ブラウザが実際に描く色（canvas 実測） | `#737373` — 白地に **4.74:1**（合格）                |
| axe が読み取った色                    | `#7c7c7c` / 背景 `#fdfdfd` — **4.1:1**（違反と報告） |

上の「なぜ canvas で描いて測るのか」と同じ問題が、axe 側でも起きている。
配色トークンが oklch である限り再発するので、**axe-core を上げたときは
一度除外を外して false positive が消えたか確かめること**。
